## 🚨 发现的问题

### 🔴 Critical：JWT_SECRET_KEY 强度不足

**当前配置**：
```
JWT_SECRET_KEY='super-secret-wind-chan-key-change-me'
```

**问题分析**：
- ❌ 长度：42 字符（满足最低要求 32 字符）
- ❌ 熵值不足：包含可读单词（`super`, `secret`, `wind`, `chan`, `key`, `change`, `me`）
- ❌ 可预测性高：容易被字典攻击破解
- ❌ 示例性质：明显是占位符密钥（`change-me`）

**安全风险**：
- 攻击者可能通过字典攻击或暴力破解获取密钥
- 一旦密钥泄露，可伪造任意管理员 token
- 影响所有需要认证的接口（文章管理、上传文件等）

**修复方案**：
立即替换为高熵随机密钥！

```bash
# 在命令行执行以下命令生成安全密钥
python -c "import secrets; print(secrets.token_hex(32))"

# 示例输出（64 个十六进制字符）：
# 8f4a2b7c9d1e3f5a6b8c0d2e4f6a8b9c1d3e5f7a9b0c2d4e6f8a0b2c4d6e8f0a
```

**修改 .env**：
```env
# 替换为刚才生成的随机密钥
JWT_SECRET_KEY=8f4a2b7c9d1e3f5a6b8c0d2e4f6a8b9c1d3e5f7a9b0c2d4e6f8a0b2c4d6e8f0a
```

## 🔐 密钥管理最佳实践

### ✅ 应该做的

1. **使用密码管理器**：将生成的密钥存入 1Password、Bitwarden 等
2. **定期轮换**：每 3-6 个月更换一次 JWT 密钥（需通知用户重新登录）
3. **分环境管理**：开发/测试/生产使用不同的密钥
4. **备份密钥**：妥善保存密钥的离线备份（加密存储）

### ❌ 不应该做的

1. ❌ 将密钥硬编码在代码中
2. ❌ 使用可读单词或短语作为密钥
3. ❌ 在多个项目间复用密钥
4. ❌ 通过聊天工具明文传输密钥
5. ❌ 将 `.env` 提交到版本控制系统

## 📞 遇到问题？

**Q1: 更换密钥后所有用户需要重新登录吗？**  
A: 是的。JWT 是无状态的，旧 token 将无法通过新密钥验证。

**Q2: 如何在不影响用户的情况下轮换密钥？**  
A: 使用密钥版本机制（高级）：
- 同时支持新旧两个密钥解密
- 新 token 用新密钥签发
- 旧 token 在有效期内仍可用旧密钥验证
- 等待旧 token 全部过期后移除旧密钥

**Q3: 忘记密钥怎么办？**  
A: 
1. 如有备份，从备份恢复
2. 如无备份，生成新密钥（所有用户需重新登录）
3. 管理员可重置自己的密码：`flask create-admin`
